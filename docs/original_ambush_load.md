# Оригинал: маркировка засад и изменение загрузки

Повторный разбор `original/king.exe`, 2026-10-15/16. Ниже — реконструкция
управления по дизассемблеру, не исходники разработчиков. Неизвестным полям
и функциям не присвоены выдуманные игровые значения.

## Воспроизводимая проверка

```sh
python3 tools/ambush_original_probe.py
python3 tools/script_rng_oracle.py
uv run --with unicorn==2.1.4 python tools/load_guilt_oracle.py
r2 -N -q -e scr.color=0 -c 'af @ 0x42c0b0; pdc @ 0x42c0b0' original/king.exe
```

Первый инструмент статически сверяет 35 инструкций/ветвлений/констант/целей
вызовов с локальным исполняемым файлом. Он **не исполняет оригинальный
обработчик** и не доказывает семантику полей. Второй исполняет оригинальное
ядро PRNG в ESIL: 64/64 результатов совпадают с портом. Третий исполняет
оригинальный обход грузов, x87-сравнения, записи и PRNG в Unicorn x86:
1680/1680 случаев совпадают с C++ (840 входов по одному и по два вызова).
Подменён только lookup текущего игрока; реальные обработчики остальных
подсистем и полноценная игра не запускаются. Вывод `pdc` требует
ручной сверки с инструкциями: x87, SEH и обёртки PlayerId нельзя принимать
за корректный C++ автоматически.

## `markAmbushes`, 0x42c0b0

После удаления диагностической обвязки эквивалентное управление выглядит так:

```cpp
for (auto* a : ambushes) {
    a->armed = false; // +0xf0, запись 0x42c140
    if (a->classId == 2) { // POLICE
        a->armed = rng.bounded(1000000) < 300000;
    } else if (a->classId == 1) { // MAFIA
        auto* p = resolveCurrentPlayer(); // 0x477b60
        if (!(readDouble(p, 0xe0) > 0.0 || readByte(p, 0xc9) != 0))
            continue;
        if (!(readDouble(p, 0x300) > 0.2)) // 0x429820
            continue;
        a->armed = rng.bounded(1000000) < 300000;
    }
}
```

Смещения уточнены: `0x42c1d8` прибавляет **0xc8**, затем читает `+0x18`
и `+1`. Это абсолютные смещения **0xe0 / 0xc9**, не прежние ошибочные
0x218 / 0x201. Сравнения строгие: равенство 0 / 0.2 не проходит;
unordered x87 comparison тоже не проходит ветку `>`.

Та же пара условий `+0xe0/+0xc9` в `0x40b242..0x40b268` вызывает
`mafiaOnHim(PlayerId)` (`0x40aa00`, имя присутствует в диагностической строке).
Блок `player+0xc8` передаётся и в `cleanBeforeLaw` (`0x430b2a` → `0x4308e0`).
Это связь с состоянием преследования/учёта нарушений, **не доказательство**,
что оба условия эквивалентны тегу груза `formafia`.

**Уточнение базы указателя 2026-10-16:** `0x40a9f0` возвращает `node+8`,
то есть начало payload, а `0x477b60` возвращает handle на узел списка.
Поэтому `node+0x300` — **payload+0x2f8**, не payload+0x300.
Писатель нормализованной доли — `0x41fed3` внутри `updateRating`;
регистрация имени/entry — `0x434d41/0x434d48`, entry `0x41fcf0`.
Там агрегируются результаты `0x41fca0` для игрока и связанных объектов;
в payload+0x300 сохраняется ненормированная величина (`0x41feb2/0x41feb8`),
в payload+0x2f8 — её отношение к общей сумме (`0x41fecf/0x41fed3`).
`0x41fca0` использует `0x41b910` для классов 1/2, иначе возвращает ноль.
Точный перевод всей экономики/подчинённого транспорта в эти показатели
пока не восстановлен; путать raw-величину с нормированной долей нельзя.

## `accountForChangeInLoadState`, 0x442c60

Имя присутствует в диагностической строке `0x66f124`. Существенные вызовы
идут в следующем порядке; неизвестные функции оставлены по адресам:

```cpp
f442850(player); // accountForGuilt, диагностическое имя 0x66f100
f425790(player);
f41ef90(player);
f477210(player);
if (f417660(player))
    f56f6d0();
auto* object = f477880(player);
if (object) {
    auto value = f4715a0(object, 0, 0, 1);
    writeDouble(player, 0x3c0,
                value * 0.2 + readDouble(player, 0x3c0) * 0.8);
} else {
    player->flags60 &= 0xfeefffff;
}
markAmbushes(); // call 0x442d74, без аргумента player
```

Восемь вспомогательных call sites до маркировки, два условных. Этот список
не включает диагностические вызовы и не раскрывает вложенные эффекты.
`accountForGuilt` содержит отдельное обращение к PRNG (`0x442b90..0x442ba4`)
до возврата в обработчик. Следовательно, одинаковый PRNG и верная формула
маркировки **недостаточны для совпадения последовательности событий**.

## Что ещё не перенесено точно

### Перенесено 2026-10-16: ядро accountForGuilt

`src/script/LoadGuilt.h` повторяет `0x44289c..0x442bcb` на явных входах.
Состояние содержит упорядоченные записи груза, основной/связанный flag 2,
поле записи +0x40, сохраняемую метку +0x88, флаги контейнера и долю игрока.
В `ScriptRuntime` добавлен типизированный путь: этот обход, затем
markAmbushes на **том же** EngineRandom и числовые условия node+0xe0>0 /
mafiaWanted / доля>0.2. Он не заменяет остальные load-change helpers.

Подтверждённые детали, включая нетривиальное поведение оригинала:

- флаги переносятся между записями; ветка `0x4429ba` проверяет накопленный
  illegal, а не только наличие связанного груза у текущей записи;
- formafia учитывается только при доле **>0.15**, не при любой загрузке;
- проверки используют rnd(1000000) с порогами 500000 / 200000, поле +0x40
  сравнивается с **10000**; equality/unordered ветки сохранены;
- при +0x88 == -1 оригинал расходует случайное число и записывает **0**,
  а не случайное число. Повторный callback использует сохранённую метку;
- при накопленном illegal и mafia, метка 1 снимает illegal, оставляя mafia;
  другая метка снимает mafia, оставляя illegal;
- флаг node+0x108 дополнительно перебрасывается только при flag 2 контейнера.

Дифференциальный тест сравнивает все три выходных флага, метки записей и
**следующее** число генератора. Он нашёл две ошибки первой версии переноса
(накопленный illegal / исключение marker==1); оба случая теперь входят в
шесть постоянных golden-регрессий обычного build_script_check.

### Открыто: подключение реального состояния App

App сейчас вызывает только ядро маркировки и передаёт два bool от `formafia`.
Это временная политика порта, не реализация приведённого обработчика.
Для замены нужны настоящие связанные записи груза и доли/транспорт компаний,
писатели числовых полей блока `+0xc8`, остальные вызовы load-change, полный порядок
PRNG и первоначальная инициализация. Подставлять ноль или единицу вместо
неизвестной доли только ради подключения нового ядра нельзя.
Нельзя закрывать этот пункт зелёными тестами только bool-ядра.
